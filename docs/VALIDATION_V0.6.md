# MindBody V0.6 开发与验证报告

日期：2026-11-19。应用版本 0.6.0。基于同一工作区已完成但尚未提交的 V0.5 继续开发，没有重建、提交、推送、部署或修改远程配置。没有读取或上传日常端口中用户的私人记录；没有实连外部 LLM。

## 1. 已实现范围

- 首页新增身心洞察入口，保留记录、历史、7/30 天趋势、JSON 导出、确认删除，AI 周报保持禁用。
- DailyContext/KnowledgeCard/DailyInsight/InsightConversation 等类型；今日与近 7 日事实由程序计算，后端再核对。null、0、缺少今日、仅备注记录明确区分，单日不声称存在变化。
- psychology/tcm 两个独立知识域共 4 张卡，标签/关键词检索。显示来源 URL、定位、证据类型、核对范围及不确定性；无出处时不强行解释。
- 洞察页本地预览不联网；心理/中医/综合追问，每次授权后才发送摘要；Mock 无 Key 即可用，真实模式可配置。
- 自选 1 项微行动，可取消/替换；聊天与行动只在页面内存，重进/刷新重置。
- 本机 FastAPI、Pydantic/JSON Schema、同域候选 ID 校验、危险问题分流、输出/网络故障降级。Key 只在服务端进程环境，不持久化请求/结果、不记录请求体。

真实 AI 是受约束的卡片/反思句选择器，解释正文取自来源核对卡，不是开放式心理咨询。没有生成医疗判断、治疗、用药或推断量表分数。

- 只访问独立 5175 测试端口，localhost 与 127.0.0.1 两个测试来源均使用虚构记录；不访问日常 5173 浏览器存储。
- 虚构样例：情绪 4、压力 2、睡眠 0、精力空。洞察准确展示 0/未填、每项填写不足两天、两个知识来源。
- 准备按钮后授权框列出的确切摘要没有 bodyNote/createdAt/updatedAt/过去聊天；默认取消，取消后仍为本地预览；同意后显示 Mock 服务回应。
- 心理视角服务回应只有心理卡；切换清空聊天。虚构危险问题返回“专业支持引导”，没有外部模型调用。
- 真实模型禁用时提示未发送记录。选择第二个微行动后第一个 aria-pressed=false、第二个=true；刷新聊天/选择清除，持久化记录仍可读取。

## 5. 如何手动验收

1. 按 README 安装 `.venv` 依赖；两个终端分别启动 `pnpm dev:h5` 和本机 uvicorn（8000，默认 Mock）。固定使用 http://127.0.0.1:5173/。测试删除请使用另一个测试端口的虚构数据。
2. 无今日记录时进入洞察，应引导记录，不使用昨天替代。填写一项或几项虚构状态；可将睡眠设 0，留空精力。保存后回首页再进洞察，应与记录一致，不补分、不称长期趋势。
3. 阅读心理/中医卡与来源、证据类型、局限。进入页面应为“本地教育预览”；API 未启动也能阅读这部分。
4. 输入虚构问题，准备摘要。先点取消，确认没有服务回应；再准备，核对确切 JSON 没有备注/时间戳，然后明确授权。应显示 Mock 服务回应。浏览器网络面板中取消没有 POST，授权才有 POST。
5. 分别切换心理、中医、综合，每次重新授权；聊天不跨视角保留。选择两个不同微行动，应只有后一项选中，刷新后清除选择/聊天。
6. 可用虚构范围测试“请给我开方”观察范围限制，不要输入真实危险经历或身份信息。测试离线时停止自己启动的 API；本地预览仍可读，准备请求会清楚报错。
7. 在开发者工具中检查 320/390/1280，授权对话框能滚动、取消、按 Escape。回归每日保存/刷新、历史、7/30 天趋势、JSON 导出；删除只对隔离虚构数据操作。

自动化验证多日记录无需修改设备日期或浏览器真实存储；`pnpm check` 已覆盖跨月年与缺项。真实模型需用户另行配置服务端环境并用虚构数据验证供应商兼容性，未自动开启。

## 6. 已知限制与接续

- 4 张知识卡只是来源核对示例，尚无临床专家审核。传统文本、术语标准与现代公共健康教育的证据类型不同，不据此作个体诊断或疗效结论。
- 追问使用当前问题/摘要的关键词与受控选择，不发送过去聊天；回复丰富程度有限。微行动不持久化，没有打卡/提醒/成效分析。
- 风险关键词不能覆盖所有危险表达，不是危机识别或急救服务。JSON Schema/引用约束能限制模型正文，不能替代专业内容审核。
- 真实 LLM 适配器已用 HTTP 替身测结构与故障，没有供应商实连；并非所有兼容接口支持 json_schema，失败会降级。
- API 仅本机开发，没有身份认证/限流，不适合公开部署；配置从进程环境读取，不自动载入 .env。无服务端健康存储/日志，但外部供应商政策须用户核对。
- 前端/后端共用卡片文件，更新后需要重启 API；旧页面与新后端卡片不一致时会拒绝响应并提示，不静默采用陌生内容。
- 原本地存储未加密、跨标签无事务、浏览器清理会丢数据等限制仍然存在。没有云同步、JSON 导入还原、数据库、AI 周报或跨端实测。
- 周报可复用程序摘要、检索/引用和授权适配，仍需专用契约与验收；本批次到此停止。

## 7. 三个学习点

1. **类型与运行时校验**：TypeScript 在开发时检查形状；Pydantic/前端验证器在运行时检查真正收到的 JSON，二者解决不同时间点的问题。
2. **纯函数与单一数据来源**：记录只存一次，趋势/洞察都由同一记录计算；null 表示没填，0 表示真实填写，不能用 `value || 默认值` 混为一谈。
3. **服务边界与授权快照**：页面负责交互，服务模块负责传输，后端负责密钥和模型；用户确认的是本次不可变摘要，每次请求单独授权，过期异步结果也要拦截。
