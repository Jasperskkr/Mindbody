## 3. 统一接口、错误与数据流

```ts
loadDailyRecord(date: string): Promise<DailyRecord | null>
saveDailyRecord(input: DailyRecordInput): Promise<DailyRecord>
listDailyRecords(): Promise<DailyRecord[]>
deleteDailyRecord(date: string): Promise<boolean>
deleteAllDailyRecords(): Promise<number>
```

存储键仍为 `mindbody:daily-record:v1:YYYY-MM-DD`，值仍为 JSON 字符串 `{version:1, record}`。一天一条，更新保留 createdAt、重设 updatedAt。所有页面只通过上述接口读写；列表按日期倒序，不能返回悄悄略去坏记录的不完整结果。

三种情况明确区分：没记录返回 null/[]；记录有缺项保持 undefined；读取失败或坏数据抛错。全空的已存记录是坏记录，不能当作没记录。错误类型为 DailyRecordStorageError，含 code、可选 date、批量删除的 deletedCount；各错误码及页面处理见 IMPLEMENTATION_HANDOFF.md。

数据流如下：

1. 记录页 `form` 接收输入，`parseRecordForm` 转换与校验；存储模块再次校验，写入 uni.setStorage，成功后反馈。
2. 首页 onShow 调用 loadDailyRecord，`toDailyOverview` 转文字，Vue computed 更新卡片。
3. 历史页 onShow 调用 listDailyRecords，唯一的内存 records 数组供卡片与趋势使用，不另存历史或图表缓存。
4. `buildHealthTrends(records, 7或30, 今天)` 只计算不写入；缺失变成 null，各项平均值只用实际填写天数。
5. 导出再次 listDailyRecords → 校验并序列化 → H5 适配层触发本机下载；包为 `{schemaVersion:1, exportedAt, records}`。
6. 删除由明确点击与确认触发；存储层定向删除并验证，页面无论成功失败都重读；趋势随 computed 重算，其他页面重新显示时也重读。

示例：两天睡眠分别为 0、8，中间一天没填；平均为 `(0+8)/2=4`，不是除以 3，更不能把没填当 0。

- 仅验证 H5 Chromium；微信小程序/App 尚未编译和真机测试，导出适配明确未实现。Safari、真实手机、屏幕阅读器全流程尚未验证。
- 当前只填写当天，不选择/编辑历史日期；无分页、导入恢复、回收站、损坏数据修复、云备份、登录或后端。JSON 文件可解析，但当前产品没有导入按钮。

- uni 本地存储不提供跨键事务。批量预检防止已损坏记录被静默处理，操作期间变化检查是尽力防护，读取至删除之间仍非原子操作；中途失败可能已删除一部分，页面如实提示并重读。避免同时在多个标签中修改。

## 8. 手动验收步骤

日常预览：在项目根目录运行 `pnpm dev:h5`，打开 http://127.0.0.1:5173/；若服务已运行，无需再启动。新增路由后需要重启旧开发服务，再刷新页面。

```powershell

pnpm exec uni --host 127.0.0.1 --port 5176 --strictPort
```

打开 http://localhost:5176/，固定这个地址完成测试。若该地址已有自己的记录，另选空闲测试端口，不要清理它。

1. 首页应为“尚未记录”；进入历史，检查空态与填写引导；切趋势应显示无数据。
2. 每日记录仅填情绪 4、压力 2、睡眠 0、备注“虚构测试”，精力留空并保存。返回首页：情绪/压力/0 小时正确，精力“未填写”。
3. 历史列表出现当天记录，展开检查备注和时间戳；刷新浏览器仍存在。再次保存当天时首次时间不变。
4. 趋势切换 7/30 天，检查日期范围、每项填写天数、方向/单位与单日不足提示；睡眠逐日数值今天为 0，其余缺失不能显示 0。
5. 导出 JSON，用文本编辑器或 JSON 解析工具核对版本、导出时间、records 数量与原字段；未填 energy 不出现，sleepHours 是数字 0。
6. 详情点击删除，应显示日期与不可恢复说明；先取消并刷新，应保持原记录。再确认删除，历史/趋势更新，返回首页为空态。
7. 新增一条虚构记录；清空入口先确认范围，第二步取消，刷新仍有记录。再次两步确认后检查历史、趋势、首页及记录页为空态。

手动界面当前只填当天；多日/跨年排序与统计请运行 `pnpm test` 查看隔离测试结果，或自然积累多天记录，不通过改系统日期制造真实数据。

## 9. AI 周报接口准备与学习重点

已经可复用 DailyRecord、listDailyRecords、7 日趋势窗口、每项填写数/平均值和带版本号的 JSON 格式。这些是数据读取基础，还不是周报服务。周报输入/输出专属类型、发送数据范围、用户同意、服务端密钥、模型调用与输出校验均未实现；后续需单独授权设计。

本批次最值得学习的三个工程概念：

1. **分层与数据契约**：类型约定字段，运行时校验检查实际内容；存储只读写，纯工具只计算，页面组织交互，组件展示。改图表样式不需要改保存方式。
2. **单一数据来源与派生状态**：真正记录只存一份，历史和图表从读取结果生成。undefined/null 表示没填，0 是用户明确输入；不能用 `if (value)` 混为一谈。
3. **异步操作与集成验证**：Promise/await 等待结果，确认框只表达意愿，重读才确认当前状态。分层测试之外，再走 A–F 能发现“每个函数单独没错，但页面衔接出错”的问题。
