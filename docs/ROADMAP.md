# MindBody 开发路线

每次只挑选一个可验证的小任务。完成当前任务后由用户决定是否继续，不自动跨阶段。

## 第一阶段：初始化与首页（V0.1，已完成）

状态：已完成。2026-11-19 整理第一阶段成果并同步至 GitHub；未进入第二阶段。

目标：建立可运行、可读懂的基础，确认移动端首页的方向。

- 项目配置、运行与类型检查命令。
- 需求文档、协作约定、开发路线。
- 使用虚构数据的首页、两个占位入口、禁用的 AI 周报入口。
- Web 构建与浏览器检查。

## 第二阶段：每日记录（V0.2，已完成）

状态：本次范围已完成并验证。用户已于 2026-11-19 授权将每日记录与首页联动成果提交并推送至现有 GitHub 仓库；仅同步源码、配置、测试与文档，不部署站点。

用户于 2026-11-19 授权本次任务：实现每日记录表单，完成情绪、睡眠、精力、压力、身体感受输入、输入校验、本地保存及刷新回填。

首次交付：可跳过字段和明确量表方向、版本化的按日存储、读取/保存失败反馈、虚构数据自动测试和手机布局检查。详情见 `docs/VALIDATION_V0.2.md`。首次交付时首页仍显示模拟概览。

重新打开当天记录后可以补充并再次保存，保留首次创建时间。不实现历史记录管理、复杂编辑或删除。

补充小任务（用户已授权，已完成并验证）：首页读取当天本地记录，保存后返回或刷新即可显示；缺失指标显示“未填写”，没有记录和读取失败有不同提示，支持重试。首页与表单共用量表文字，不另存概览数据。验证见 `docs/VALIDATION_HOME.md`，教学见 `docs/DATA_FLOW.md`。

此处结束本次开发。下一项建议是只读的历史记录列表，尚未开始；须由用户另行授权，暂不实现趋势图、删除或导出。

## 第三阶段：历史与趋势

先按日期列出记录，再逐步实现单项趋势、缺失数据提示和时间范围。先使用简单方案，确有需要时再选择图表依赖。

## 第四阶段：知识卡与微习惯

先做少量有来源的静态教育内容，分别说明心理学与中医视角。微习惯从一个可选择、可完成的小目标开始。

## 第五阶段：后端与数据管理

需求明确后引入 FastAPI、数据库、认证和同步。先设计访问控制、删除和备份，再考虑部署；部署与远程推送须经用户明确要求。

## 第六阶段：AI 周报

先定义周报结构与边界，使用虚构样例验证缺失记录、错误输出与隐私处理。接入真实服务前确定用户授权与服务端密钥管理。

## 第七阶段：微信小程序与 App

复用页面和业务逻辑，分别安装目标平台编译依赖、配置平台标识，并在各自工具或真机测试。uni-app 的代码可复用不等于所有平台已经兼容。
