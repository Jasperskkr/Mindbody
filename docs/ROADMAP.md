# MindBody 开发路线

每次只挑选一个可验证的小任务。完成当前任务后由用户决定是否继续，不自动跨阶段。

## 第一阶段：初始化与首页（本次）

状态：已完成。2026-11-19 整理第一阶段成果并同步至 GitHub；未进入第二阶段。

目标：建立可运行、可读懂的基础，确认移动端首页的方向。

- 项目配置、运行与类型检查命令。
- 需求文档、协作约定、开发路线。
- 使用虚构数据的首页、两个占位入口、禁用的 AI 周报入口。
- Web 构建与浏览器检查。

## 第二阶段：每日记录（下一步建议）

第一个小任务：实现“每日记录表单”，完成情绪、睡眠、精力、压力、身体感受输入，并保存一条记录到本地；刷新后仍能读取。

这个小任务需要先约定数据结构、可跳过字段、基础输入校验和保存失败反馈。模拟数据与真实数据必须明确区分，真实记录不得进入 Git。

后续再分别做：编辑当天记录、空状态、首页展示本地记录、删除与导出。不要一次全部实现。

## 第三阶段：历史与趋势

先按日期列出记录，再逐步实现单项趋势、缺失数据提示和时间范围。先使用简单方案，确有需要时再选择图表依赖。

## 第四阶段：知识卡与微习惯

先做少量有来源的静态教育内容，分别说明心理学与中医视角。微习惯从一个可选择、可完成的小目标开始。

## 第五阶段：后端与数据管理

需求明确后引入 FastAPI、数据库、认证和同步。先设计访问控制、删除和备份，再考虑部署；部署与远程推送须经用户明确要求。

## 第六阶段：AI 周报

先定义周报结构与边界，使用虚构样例验证缺失记录、错误输出与隐私处理。接入真实服务前确定用户授权与服务端密钥管理。

## 第七阶段：微信小程序与 App

复用页面和业务逻辑，分别安装目标平台编译依赖、配置平台标识，并在各自工具或真机测试。uni-app 的代码可复用不等于所有平台已经兼容。
