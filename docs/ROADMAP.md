# MindBody 开发路线

更新日期：2026-11-25。当前版本 V0.7。用户已授权连续完成专业知识库工程化，并持续授权每批检查通过后提交、推送至现有 GitHub 仓库；批次结束后不自动开发新功能或部署。

## V0.1：初始化与首页（已完成）

uni-app + Vue 3 + TypeScript 基础、移动端模拟首页、开发/构建命令、产品与协作文档。已按用户当时授权同步至 GitHub，作为历史基线。

## V0.2：每日记录与首页联动（已完成）

当天情绪/压力/精力/睡眠/身体感受表单、输入校验、v1 本地保存与回填、首页读取当天记录。缺项不补分，睡眠 0 有效，失败不覆盖。按用户当时授权提交并推送，基线提交 543f197。验证见 VALIDATION_V0.2.md、VALIDATION_HOME.md。

## V0.3–V0.5：本地数据管理与趋势（本批次已实现）

用户明确授权合并连续开发，未授权提交、推送或部署。

1. 统一数据层：按日读写、倒序列表、单条/全部定向删除、错误码及完整性检查；原数据格式不变。
2. 历史页：从首页进入，只读详情、缺项、空态、失败重试和重新进入刷新。
3. 数据管理：H5 JSON 导出、单条确认删除、默认取消的双重清空；操作后重读，不清理其他应用数据。
4. 趋势：7/30 日、四项图表、逐日数值和已填天统计；缺失留白，无医疗判断。
5. 集成：虚构内存存储运行 A–F、类型/构建、H5 浏览器操作与 320/390/1280 布局验证，更新文档与 0.5.0 版本。

阶段接口与结果见 IMPLEMENTATION_HANDOFF.md，最终结果及限制见 VALIDATION_V0.5.md，教学见 DATA_FLOW.md。

本批次到此结束，改动保留本地。尚未实现历史编辑、分页、JSON 导入还原、回收站、跨标签冲突合并、损坏数据修复或备份迁移。

## V0.6：双视角身心洞察 MVP（已实现）

1. DailyContext 等契约：程序计算今日/7 日数值、null 与 0、样本数量和短窗口变化，服务端重新核对。
2. 独立心理/中医 JSON 知识域：4 张来源核对卡，标签/关键词检索，明确证据类型、核对范围与不确定性。
3. 身心洞察页面：本地预览、知识来源、心理/中医/综合对话模式、一项自选微行动、空态/重试。
4. 本机 FastAPI：默认 Mock、服务端密钥和可选真实模型、逐次摘要授权、JSON Schema、候选引用验证、风险请求与模型失败降级。
5. 集成：前后端自动化、跨语言契约、真实本机 Mock HTTP 和 320/390/1280 布局。详情与限制见 VALIDATION_V0.6.md，阶段交接见 IMPLEMENTATION_V0.6.md。

本批次不提交、推送或部署。真实模型只选择卡片/反思句 ID；无自由医疗对话、无临床审核、无聊天持久化、无微习惯打卡。真实供应商端到端、小程序/App 未验证。

## V0.7：知识库工程化（已实现）

保留 4 张稳定 ID 的卡与四个页面。新增来源目录、版本绑定、授权用途、独立专业审核、Chunk 结构；CLI 校验/草稿/修改/审核/归档及完整快照生成；一份评分规则生成两端代码，每域 Top-K，knowledgeHash 门禁。无新全文、Embedding、数据库或 Agent。

基线测试重新运行，新增隔离维护、跨语言检索一致性及版本门禁测试；结果见 VALIDATION_V0.7.md，交接见 IMPLEMENTATION_V0.7.md。教程从 KNOWLEDGE_BASE.md 开始。

## 后续：AI 周报（须单独授权）

已有 DailyRecord 列表、DailyContext、每项统计、知识引用、授权与结构化服务适配可以复用。周报仍需独立输入/输出契约和验收，不能把当前卡片选择器直接称作周报；不得默认上传原始记录，不据此诊断或治疗。V0.6 未实连外部模型。

## 后续：知识卡、微习惯

V0.6 已有少量有来源的教育卡与页面内自选微行动。后续是否扩充内容、引入专业审核或保存打卡，由用户另行决定。

## 后续：后端与跨端

V0.6 已引入仅本机使用的 FastAPI。数据库、认证、同步和公开部署仍未实现，须先明确访问控制、删除与备份。微信小程序/App 需分别编译和真机验证，尤其文件导出和本机 API 地址需平台适配，不能因 uni-app 复用就宣称全部兼容。
