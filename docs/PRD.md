# MindBody 产品需求（PRD）

更新日期：2026-11-25。当前版本：V0.7，双领域知识库工程化。当前增量见第 13 节，之前章节保留对应版本的验收背景和继续适用的功能。

## 1. 为什么做

先为自己建立一个能长期使用的身心记录工具，通过日常记录和趋势了解自己的状态。以可持续维护的真实产品为目标，同时让开发者在小步实现中学习软件开发。

## 2. 用户与定位

首位用户是产品开发者本人；未来再考虑更多个人用户。

MindBody 是健康记录、趋势观察和健康教育产品。情绪和压力是用户的主观感受，不能被解释为诊断结果。产品不提供自动疾病诊断、开方、药物推荐或心理治疗，不生成无依据的“健康总分”。

## 3. 平台与技术方向

| 项目 | 当前选择 | 后续方向 |
| --- | --- | --- |
| 前端 | uni-app、Vue 3、TypeScript，优先移动端 Web | 逐步验证微信小程序与手机 App |
| 数据 | 首页、记录页、历史/趋势共用统一的本地记录模块 | 后续再考虑数据库和同步 |
| 后端 | 本机 Python + FastAPI，仅洞察 API，无数据库 | 公开服务前另行设计认证、限流与部署 |
| AI | 本地预览、Mock 和可选受控 LLM 选择；周报禁用 | 丰富对话或周报须独立授权与验证 |
| 依赖 | uni-app 必要运行及构建依赖 | 无明确收益不引入 UI 库、状态库、图表库 |

## 4. 产品功能方向

以下为产品规划，并非本次全部实现。

| 功能 | 用户价值 | 初步范围 |
| --- | --- | --- |
| 每日记录 | 用较低负担留下当天感受 | 情绪、睡眠、精力、压力、身体感受；允许跳过字段 |
| 历史与趋势 | 回顾变化，发现值得关注的生活模式 | 按日期查看、简单趋势；不把相关性写成因果 |
| AI 周报 | 汇总一周已记录的内容 | 忠于原始记录，标明缺失，避免诊断和治疗建议 |
| 知识卡 | 学习心理学与中医的健康教育知识 | 双视角分别标注来源与适用边界，不给个体辨证结论 |
| 微习惯 | 支持可持续的小行动 | 自选小目标、简单完成记录，不制造连续打卡压力 |

## 5. 第一阶段：已完成的首页基线

创建可运行的项目、必要文档和一个移动端友好的首页。

首页包含：

1. 应用名称 MindBody、温和的欢迎语。
2. 按设备本地日期显示今天的年月日与星期。
3. 今日状态概览：模拟情绪、睡眠、精力、压力及身体感受。
4. 明确的“模拟数据”标记，避免误认为已记录的真实状态。
5. “每日记录”入口，第一阶段为占位提示；V0.2 改为打开记录页。
6. “历史趋势”入口，点击显示尚未开放的提示。
7. “AI 周报”入口，真实禁用并标注即将开放。
8. 简短的产品用途说明。

本阶段不实现表单、持久化、历史页面、真实图表、知识卡系统、习惯系统、后端、登录、AI 或部署。提示弹窗仅让首页入口可理解，不代表后续功能已经完成。

## 6. 视觉与交互要求

- 移动端优先，至少检查 320px、390px 与桌面宽度；无横向溢出。
- 米白背景、柔和绿色、低饱和色卡片，避免医疗警报感和评价感。
- 移动端单列，桌面适度分栏，阅读区域设置最大宽度。
- 使用可操作的按钮、清楚的点击反馈和键盘焦点；AI 禁用状态可识别。
- 不依赖远程字体、图片或第三方跟踪服务。

## 7. 数据与隐私

- 第一阶段没有存储逻辑；V0.2 允许用户在记录页保存本机输入，不上传。
- 第一阶段模拟示例保留在 `src/data/mock.ts`，当前页面不再使用；类型放在 `src/types/health.ts`，首页不生成或保存另一份记录。
- 本地存储未加密；不同浏览器、地址或端口的数据相互隔离，清理浏览器数据可能丢失记录。
- 当前存储键和数据包均使用版本 1，不迁移。V0.5 允许用户主动导出/删除已校验记录；不兼容或损坏数据保持原样，阻止覆盖、完整导出与批量清空，不静默遗漏。
- 密钥只能留在后续服务端；不能放进前端源码或前端环境变量中。
- 源码仓库不接收真实健康记录。私有数据与导出文件使用 Git 忽略目录。

## 9. V0.2：每日身心记录与本地持久化

最初交付记录页、输入校验、保存、重新打开或刷新后的回填，以及清晰的成功/失败反馈；当时首页仍使用模拟概览。用户随后授权完成下方“首页联动”小任务。历史趋势仍为占位，AI 周报仍禁用。

### 数据规则

| 字段 | 规则 |
| --- | --- |
| `date` | 设备本地日期，`YYYY-MM-DD`；当前只填写当天，不选择历史日期 |
| `mood` | 可选整数 1–5：很低落 → 很愉快，越高情绪越愉快 |
| `stress` | 可选整数 1–5：很放松 → 很强，越高压力越强 |
| `energy` | 可选整数 1–5：很疲惫 → 很充沛，越高精力越充沛 |
| `sleepHours` | 可选数值 0–24，允许小数；0 是有效值，留空表示未填写 |
| `bodyNote` | 可选文本，最多 500 个 UTF-16 字符；保存时去除首尾空白，仅空白不算填写 |
| `createdAt` | ISO 时间，同一天第一次保存时生成，再次保存保持不变 |
| `updatedAt` | ISO 时间，每次成功保存时更新 |

- 所有字段初始留空；量表可清空，不自动补 3 分。未填字段不写入保存对象。
- 至少有一项有效内容才能保存；非法输入即使与有效内容同时存在，也会阻止整条保存。
- 再次保存更新当天记录；不提供列表编辑、删除或历史日期管理。
- 页面停留到日期变化后，保存会提示重新进入当天页面，不把旧表单自动写到新日期。

### 存储与失败处理

- 页面只调用独立存储模块，使用 `uni.getStorageInfo`、`uni.getStorage`、`uni.setStorage`。
- 按天使用键 `mindbody:daily-record:v1:YYYY-MM-DD`，保存 JSON 字符串 `{ version: 1, record: DailyRecord }`，避免覆盖其他日期。
- 先确认键是否存在，再读取和校验内容，区分首次使用、API 读取失败和数据格式异常。
- 初次读取失败时展示错误与重试按钮，暂停填写与保存；不清理、不重置已有存储。
- 每次保存前再次读取，保护已有数据并保留创建时间。写入失败时保留表单，允许重试。
- 表单有“本地未加密、清理浏览器可能丢失、不会上传”的简短说明。

### V0.2 验收

- [x] 首页通过 `uni.navigateTo` 打开记录页。
- [x] 可填写、校验并保存，重开和刷新后能回填。
- [x] 缺失字段保持缺失，0 小时正确处理。
- [x] 空表单、非法值和超长文本被阻止。
- [x] 读取/写入/损坏数据错误清楚反馈且不静默覆盖。
- [x] 320px、390px 与桌面布局正常。
- [x] `pnpm check` 通过，自动化仅使用虚构数据。

实际结果与手动验收步骤见 `docs/VALIDATION_V0.2.md`。本轮不实现趋势图、复杂编辑删除、登录同步、后端或 AI；未经用户再次要求，不继续下一项任务。

## 10. V0.2 补充：首页读取当天记录

范围：复用现有按日存储，将首页“今日状态概览”接到当天已保存记录；不增加存储副本、依赖或新功能入口。

- 首页初次打开、刷新、从记录页返回时，通过 `onShow` 重新读取设备本地当天记录，同时更新日期标题。
- 已填量表使用与表单相同的文字及方向；睡眠按保存数值显示，0 小时是有效值。
- 有记录但部分字段缺失时，该项目显示“未填写”；没有当天记录时显示“尚未记录”及填写提示，不沿用昨天或模拟数据。
- 读取期间显示加载状态；读取失败展示错误与“重新读取”，不把失败显示成尚未记录，也不展示旧的概览。
- 身体感受保留换行，长文本在窄屏内换行。未保存的表单输入不进入首页概览。
- 首页只读数据；保存仍通过记录页和同一存储模块。保存成功后返回首页即可更新，无需额外保存首页状态。

验收与执行结果见 `docs/VALIDATION_HOME.md`；数据流教学见 `docs/DATA_FLOW.md`。完成后停止，不自动实现历史趋势。

## 11. V0.5：V0.3–V0.5 综合批次

用户授权连续完成下列模块，阶段间测试和交接，不需重复确认；不授权 Git 提交、推送、部署、上传健康数据或处理真实私人记录。

### 统一数据与历史

- 保留既有 DailyRecord、v1 存储键和数据包。新增 `listDailyRecords()`、`deleteDailyRecord(date)`、`deleteAllDailyRecords()`，旧读取/保存接口继续兼容。
- 日期倒序返回完整有效列表；非法专用日期键、损坏 JSON、日期/版本/字段错误明确报错，不静默跳过或修复，不读取其他应用存储值。
- 首页历史趋势入口打开 `pages/history/index`，记录/趋势选项卡切换。历史卡显示五项感受，可展开量表方向、完整备注和时间戳，允许删除但不编辑历史。
- 没记录时引导填写；读取失败时展示重试；重新进入页面读取新数据，无列表/趋势持久化副本。

### 数据管理

- JSON 结构为 `{schemaVersion:1, exportedAt: ISO时间, records: DailyRecord[]}`；导出重新读取完整存储，保留已定义原始字段、时间戳和缺失语义，不伪造分数。
- H5 适配层使用本机下载；提示“已发起下载”，提醒自行确认文件。导出失败清晰反馈；损坏数据不会被悄悄遗漏。
- 单条删除须明确点击并确认日期。清空全部为独立危险入口，二次确认、默认取消，告知不可恢复。取消不调用删除接口。
- 仅删除当前 v1 专用记录键，禁止 clearStorage。全部预检通过才开始批量删除；失败时报告已确认删除数量，不虚报全成功。操作后重新读取列表与趋势；其他页面再次显示时重读。
- 没有导入/恢复功能；JSON 是可解析的数据备份文件，当前不能在产品中一键还原。小程序/App 导出能力未实现。

### 趋势

- 最近 7/30 个本地日历日包含今天，从早到晚绘制情绪/压力/精力/睡眠柱图；可展开逐日数值。
- 只使用 `listDailyRecords()` 的记录，通过纯函数计算，不保存趋势结果。窗口外或未来记录不计入窗口。
- 缺日期和未填指标为 null，绘制灰色无数据短线，不补 0。有效最小值用绿色圆点，睡眠 0 参与统计。
- 显示填写天数、已填天平均值、量表方向和单位；0 个样本显示无数据，1 个样本提示不足以观察变化。
- 不生成健康评分、医学判断或因果解释。不新增图表依赖。

### V0.5 验收与边界

- 自动化覆盖 A–F：保存→首页/历史/趋势→重建页面仍保留、多日排序、7/30 天、JSON 可解析且完整、单条删除、取消不变、清空后的三处空态。
- 边界覆盖无记录、单日、断续、跨月年、0 与缺项、损坏 JSON、读/写/导出/删除失败和部分清空。
- `pnpm check` 类型检查、测试和 Web 构建通过；320/390/1280 布局实测。实际结果与未验证平台见 `docs/VALIDATION_V0.5.md`。
- 不实现 LLM/Agent/RAG、心理诊断、中医辨证、治疗建议、登录/同步、后端数据库或付费。AI 入口保持禁用。
- 本地存储未加密，不支持跨标签原子事务或实时同步；批量删除有明确的部分失败边界。大量历史记录暂未分页，后续按实际需要优化。

## 12. V0.6：双视角身心洞察 MVP

用户授权连续实现本节全部模块；不授权提交、推送、部署或处理真实私人记录。V0.5 的不接后端/AI 说明只代表其历史范围，本版本按以下边界扩展。

### 数据契约与事实

- 复用既有记录和存储接口，不改 v1 格式，不持久化洞察副本。
- DailyContext 含今日四项数值、最近 7 个本地日历日的有效样本及程序统计；指标缺失为 null，睡眠 0 有效，至少两次该项填写才有首末差值。
- 不发送身体备注、记录时间戳、身份信息或过去聊天。无今日记录不给个体解释；单日不描述变化，7 日观察不能称长期趋势，不推断原因或疾病。
- 前端计算全部事实，服务端用样本重新核对日期、统计和 today；LLM 无权改写数字。

### 双知识域

- psychology/tcm 独立 JSON，首版 4 张卡，以标签/关键词检索，无向量库。
- 每卡有稳定 ID、域、原创短文、局限、证据类型、来源 URL/定位、核对日期/范围及版本。
- 心理卡参照 NIMH 自我关怀材料，中医卡分为古代养生文本与 WHO 术语阅读边界；传统文本或术语标准不作为个体疗效证据。
- source_checked 表示核对来源与转述，并非临床专家审核；未检索到卡片就明确说无匹配内容。两域不互相推导。

### 页面、对话与微行动

- 首页新增“身心洞察”，保留每日/历史入口和禁用的周报。
- 洞察页 onShow 重新读取完整有效记录，展示程序事实、双域教育预览、来源/不确定性；空态引导记录，读取失败可重试。
- 可选择心理/中医/综合对话与 Mock/真实模式。每个问题独立请求，过去聊天不上传；切换视角清除本页聊天，刷新/重新进入清除聊天及行动选择。
- LLM 只返回本次候选引用 ID 与受控反思句 ID，不生成自由医疗文案。首版对话能力有限，不能声称提供心理治疗或完整上下文咨询。
- 从 3 个固定微行动中最多自选 1 项，也可取消；只在页面内存，无打卡、提醒或疗效承诺。

### 服务、授权与降级

- 本机 FastAPI 默认 Mock，无 Key 可运行；可选真实模式使用服务端环境中的 HTTPS 兼容服务配置与密钥，无前端密钥。
- 进入页面不发网络请求。准备按钮只 GET 非健康配置；展示确切摘要、本次问题、模式、目的地/模型后，明确授权才 POST。取消、离页和切换不发送摘要；每次请求重新授权。
- 输入采用 Pydantic 校验，ModelSelection JSON Schema 限制模型输出；引用必须属于当次检索的正确域，正文只能取审核卡，客户端再次验证。
- 无匹配、超时、API 故障、坏 JSON/引用/额外危险文案均明确降级；危险问题先固定回应，必要时引导当地紧急服务/专业人员，不调用外部模型。规则无法识别所有危险表达。
- API 不持久化请求/对话/结果，不记录请求体，关闭访问日志；请求格式错误不回显健康数据。服务商可能保留真实模式请求，授权时明确说明。
- 仅本机开发用途，未实现身份认证/限流，禁止据此宣称可以公开部署。

### 验收与未验证项

- 虚构数据覆盖缺失、0、无今日、单日/多日/跨年、无检索、坏引用、危险输出、模型失败、未授权零调用、页面离开后的迟到结果。
- 保留旧功能全部回归，执行 `pnpm check`；前端真实摘要经 Python API 返回后再用 TS 校验；浏览器独立测试地址实测 Mock 与 320/390/1280。
- 实际结果见 VALIDATION_V0.6.md。真实供应商端到端、小程序/App 未验证；无 AI 周报、数据库、登录云同步、自由医疗对话、持久化聊天、微习惯打卡。

## 13. V0.7：专业知识库工程化

- 保留四个页面、现有洞察 API 路径及 4 张稳定卡片 ID；不改健康记录存储、不迁移或清空私人数据。
- SourceDocument 独立保存来源、版本、核对与授权用途；KnowledgeCard 通过 sourceId/sourceVersion 绑定；KnowledgeChunk 仅预留结构，暂无全文切分/Embedding。
- 卡片来源核对、专业审核、传统理论/现代研究证据、授权状态分别记录。现有示例未获专业审核；原始数字来源的复制授权未知，不自动导入全文。
- CLI 提供数据校验、重复 ID/来源检查、来源登记、草稿、版本修改、审核记录、归档、正式数据构建/检查。更新回草稿、清除旧专业审核；来源更新后卡片须重新绑定核对。
- 活动、来源核对、同域、来源版本匹配、用途授权匹配且未拒绝的内容才进入正式快照；草稿/拒绝/归档不得进入正式候选。稳定 ID 不得物理移除或复用。
- 评分规则仅维护一份表达式，生成前后端适配；每域 Top-K，默认各 2、可配置 1–10。无正分结果返回空，不跨域代替；稳定排序/引用。
- manifest 与 SHA-256 快照哈希检查更新；准备请求 GET 时先比较版本，再逐次授权 POST，后端再核对。服务文件变化返回 503；哈希不一致返回 409，不调用模型。
- 兼容旧 V0.6 请求，新增字段可选；新版客户端必须检查服务哈希。旧客户端或离线静态页面不能承诺有实时撤稿能力，更新须刷新/重建网页并重启 API。
- 自动化用临时目录和虚构数据验证维护生命周期、坏关联/授权、域不互相挤占/混淆、撤回无旧索引残留、跨语言一致性及原功能回归；重新执行 pnpm check。
- 当前不实现专业人员身份认证、自动文献抓取、外部全文库、向量服务、GraphRAG、数据库集群、部署或医疗结论。
