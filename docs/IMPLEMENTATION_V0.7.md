## 接口与故障约定

- 维护 CLI：`pnpm knowledge <命令>`，默认只操作 knowledge；非默认 --root 在练习目录生成，不覆盖真实项目。源码编辑不会自动刷新正式快照。
- 编辑数据模型由 Pydantic 校验；Source/卡片/规则使用整数版本。revise 清除原审核；人工 review-card 记录实际核对范围。专业审核另行记录，AI 不能代填为已获资质审核。
- build 完整覆盖正式快照和代码，manifest 最后写入；check 只读检查，不自动修复。多文件不具备事务，失败后门禁拒绝使用，修复后重跑 build。已发布 manifest 缺失时拒绝重新初始化。
- 新增字段不改变原洞察路径/健康摘要：GET info 返回 knowledgeHash；POST 新客户端携带 hash，旧请求允许不带；API 响应附加 hash。健康 v1、四页路由、原数据字段和逐次授权语义不变。
- 新客户端在无健康输入的 GET 之后比较哈希，不一致不进入授权 POST。POST 再核对，防 GET 后服务换版；响应再次核对。409 为版本/模型不同，503 为文件/快照/生成实现过期。错误不回显私人请求，也不调用模型；本机 CORS 覆盖早期错误，页面能解释原因。
- 后端启动/请求时校验文件；build 后旧进程须重启。源变更即暂停服务，避免继续提供旧内容。网页静态快照需要刷新/重建，离线旧页面不能实时撤稿。维护期间避免并发请求。

## 后续接续

业务评分只改 retrieval.json；发布工具负责规范化与生成，不在两端各加新评分。新知识先登记来源和授权、再草稿/核对/发布；稳定 ID 永不复用。Chunk 只定义结构；将来 Embedding 须先实现授权材料切分/定位/撤回及评测，不把健康记录送入知识库。

当前不维护不可变的全文历史档案；manifest 是版本/哈希登记，作者数据保留当前内容和归档项。历史变更通过 Git 提交保存。开发验收完成后，用户于 2026-11-25 持续授权每批检查通过后提交、推送，协作约定已更新。本批次未部署、上传私人数据或引入新依赖。
